# 个人科研工作台

新前端源码和构建产物独立保存在本目录。复用项目04的采集、分析及研究想法生成能力，通过 `adapters/intelligence/` 读写仓库的 `shared/topics/<topic-id>/`。原项目04页面和构建产物保留。

当前接入04资料流程和03研究讨论；01、02及科研实验、自动论文写作、审稿尚未接入。本工作台不是四项目统一启动器。

## 安装、构建和启动

在仓库根目录：

```bash
conda activate 04
python -m pip install -r workbench/requirements.txt
cd workbench
npm ci
npm run build
cd "../projects/project-04-Intelligence Gathering"
python start.py
```

仍需按项目04 README完成原项目依赖安装和模型配置。新增后端依赖为 `pypdf`，用于提取PDF文本，不提供OCR。前端有独立 `package-lock.json`，不依赖原webui的node_modules。

- 工作台：`http://127.0.0.1:8080/workbench/`
- 原04页面：`http://127.0.0.1:8080/`
- 后端接口文档：`http://127.0.0.1:8080/docs`
- 前端开发：在本目录 `npm run dev`，默认5174端口，`/api`代理到8080。
- 单独检查：`npm run typecheck`。

修改Python后需要停止并重新启动后端。构建新工作台不会覆盖04的 `api/webui/`。生产构建保存在 `workbench/dist/`，`/workbench/materials`、`research`、`tasks`、`settings`可直接打开和刷新。

## 页面与使用过程

1. 顶部创建或选择课题，支持按名称或标识搜索，并可用上下方向键和回车选择；显示名称可以修改，稳定标识保持不变。
2. **情报收集**：采集或导入资料，按“当前课题 → 资料 → 资料文件夹 → 文件”的目录树查看附件、来源和状态。目录复选框一次选择或取消全部可读取文件（含子目录，独立于搜索、分页），部分选中时显示中间状态；图片和原始JSON等不可作为当前文本分析输入的附件不会批量勾选。每个目录可独立选择每页5、10、20、50项或全部，支持翻页、展开全部和收起全部；折叠或翻页不清空已选文件。点击文件名或预览按钮，可预览、下载、复制本地路径。手动补充附件后刷新。
3. 选择具体正文或整个文件夹，进入**想法生成**。输入选择与已有成果同样使用目录树，默认只展开课题根节点，显示“资料、研究笔记、实验方案”等分类，内部文件夹及文件由用户展开，不因为已有选择自动展开。领域筛选按关键词匹配；无匹配时会明确记录排除数量。
4. 点击“预览并冻结本次输入”。查看实际正文、字符范围、内容指纹、未使用文件和外部文献补充，再确认提交。任何选项或输入选择改变都需要重新预览。
5. **任务记录**查看状态、错误、日志、成果和原始JSONL。分析报告进入 `notes/分析报告/`；每个想法进入 `notes/研究想法/`。
6. 用Obsidian、VS Code或阅读器修改文件，页面重新读取即可看到最新内容。已提交任务仍使用原快照，新任务需要重新预览。

新页面不提供文件删除和完整在线编辑器。来源说明不是正文；摘要不是全文。用户决定选用PDF、Markdown或其他明确支持的文本输入，不自动扫描参考代码仓库。

## 输入、任务和恢复

- 默认不选输入；直接打开分析页不会选择整个课题。从资料页明确传递的选择会展示出来。
- 支持Markdown、UTF-8纯文本、README及部分代码/配置文本，可提取文本的PDF。扫描件、损坏文件和不支持格式有明确提示。
- 单文件读取上限15MB，单文件用于研究的文本最多60000字符；截断会出现在输入预览与报告中。本次正文合计超过180000字符时拒绝提交，请拆分任务。
- 分析按2500字符分段复用04规则分析，匹配领域的片段再以每批10段调用总结；报告记录筛选排除数量。每批AI总结最多180字，属于概括，不是完整原文替代。
- 想法生成使用选定全文范围；反思轮次重复使用同组证据。新颖性策略在预览时检索OpenAlex并冻结结果，不读其他课题或02知识库。
- 用户编辑的Markdown为后续读取依据；内部生成JSON不覆盖人工修订。
- `project04/data/workbench/`保存输入快照、原始模型JSON、任务状态、原始采集批次和日志，按04现有规则忽略Git。正文及参考链接的哈希写入报告，其他项目可直接使用shared文件。
- 模型配置在提交时冻结，密钥仅保留在任务内存中。模型名称和服务地址可追溯，密钥及Cookie不写入任务记录。
- 任务独立于浏览器运行；关闭浏览器后继续。服务中断不自动重跑，下次启动将未结束任务标为中断。
- “沿用原输入重试”创建新任务：分析/想法沿用旧正文快照，采用当前模型配置；采集按原检索条件重新获取。使用本次Cookie的采集需要重新填写后另建任务。
- “仅重试归档”读取已经保存的模型结果或原始采集记录，不再调用模型，不覆盖已发布且被用户修改的Markdown。
- 单人场景使用本地后台任务，采集顺序执行，不引入额外队列服务。

已知既有问题：原 `App.tsx` 和 `Terminal.tsx`引用缺失的DataExplorer、KnowledgeBaseWorkspace、DataExplorerDialog。新工作台不依赖这些组件，未擅自修复或重建旧前端。根页面静态产物可访问不等于原页面全部操作已经验收。

“保留核心采集、分析和构思”不表示新工作台已经全量覆盖原04。旧JSON/CSV/Excel批次的结构化浏览与分析、其他存储后端、旧库维护及实验相关操作仍在原路径中；不能把这些能力与工作台按选定文件工作的流程视为完全等价。

## 资料分析与研究想法的区别

| 功能 | 主要问题 | 产物 |
| --- | --- | --- |
| 资料分析 | 这些材料讲了什么、涉及哪些领域、有什么证据和可关注的方向？ | `notes/分析报告/`下的Markdown：规则分类、去重、来源证据、配置模型后的分批总结、主题及启发式候选方向 |
| 研究想法 | 基于这些材料，可以提出什么可检验的研究问题或假设，应该如何实验？ | `notes/研究想法/`下每个想法一份Markdown：假设、相关工作、研究问题、建议实验/指标、局限及人工判断位置 |

可以先分析论文，再选择分析报告和论文生成想法；也可以直接用选定资料生成想法，不强制先分析。分析中的候选方向主要是规则归纳的提示，不能等同经过模型反思的完整提案。生成提案也不等于已经证明创新性或完成实验。

## 最小验收与测试

```bash
# 仓库根目录，Conda 04
python -m pytest workbench/tests -q --tb=short

# 服务已启动时：真实HTTP导入和输入预览，不调用模型
python workbench/scripts/smoke.py

# 可选：额外公开检索一个GitHub仓库，不调用模型
python workbench/scripts/smoke.py --collect
```

脚本创建独立“工作台验收演示”课题供检查，不向真实研究课题写入。真实模型验证由用户明确选择资料、预览后在网页提交。

手工验收：创建课题 → 少量采集/导入 → 查看来源和附件 → 修改正文 → 刷新选择分析 → 查看报告 → 选择依据生成想法 → 修改想法 → 重新读取 → 重复采集核验人工编辑保留 → 关闭并重新打开页面查看任务。

测试使用临时目录和模拟HTTP模型响应，验证实际请求内容及多轮调用，不把模拟结果当作真实科研结论。

许可与依赖来源见 [NOTICE.md](NOTICE.md)。总体设计见 [docs/workbench-design.md](../docs/workbench-design.md)。

## DeepTutor研究讨论

分别使用Conda 03、04启动各自服务，不在04环境安装03依赖：

```bash
# 终端一：03按自己的README完成源码安装、初始化和模型配置
conda activate 03
cd projects/project-03-deeptutor
deeptutor start --dev

# 终端二：仓库根目录，工作台npm run build后启动04
conda activate 04
export WORKBENCH_DEEPTUTOR_FRONTEND_URL=http://127.0.0.1:3782
# 可选：独立03后端供状态检查；默认通过03前端自己的API代理
# export WORKBENCH_DEEPTUTOR_API_URL=http://127.0.0.1:8001
cd 'projects/project-04-Intelligence Gathering'
python start.py
```

03前端实际端口变动时修改`WORKBENCH_DEEPTUTOR_FRONTEND_URL`，不能将后端地址填作前端。03自己的API/WebSocket代理继续由其`DEEPTUTOR_API_BASE_URL`及启动器管理。返回工作台地址由03进程环境`WORKBENCH_PUBLIC_URL`控制，默认`http://127.0.0.1:8080`；使用其他端口时启动03前设置。没有改写.env、模型设置或03全局工作区根目录。

“去聊天”使用两个选择页共享的当前勾选，文件夹展开为明确去重清单，切换课题清空。每次点击新建交接/会话；刷新同一交接地址复用会话。栏目可点击“进入课题工作区”建立空参考会话，不自动附加全部资料。地址`/workbench/discussion?topic=<id>&handoff=<id>`支持刷新和直接打开，03登录/初始化保持原机制，独立窗口打开同一会话。

03直接绑定固定`shared/topics/<id>/`。选定资料显示在输入框原生附件区域，引用shared原文件，支持预览、移除；顶部不再展示整块说明。发送时对新文件或修改内容提供最多2000字符预览，未变化的文件仅保留引用，正文按需调用`workspace_read`，不每轮重复附加全文。卡片显示“文件引用/已附预览/已读取”，悬停可看完整路径、实际读取范围及限制；本地编辑后，重新点开预览或后续读取使用最新内容。移除不会删除原件。手动上传附件仍保留原生处理。

共享会话关闭自动问题推荐/下一句提示，目前支持普通chat；用`workspace_save`保存生成Markdown/文本到本轮outputs。exec、MCP、全局知识库/记忆和其他高级能力不在共享会话自动开放，03独立会话原能力保留。文件工具限定当前课题，但**不是仅允许本轮所选文件的严格沙箱**；扩大参考范围应先说明并取得同意。

预览生成文件→“归档”→标题及目标→确认，调用03自己的导出校验，0次模型请求，04离线仍可用。成功只短暂提示“归档成功”，不常驻显示保存路径，按钮保持“归档”；失败保留具体错误。工作台刷新后可选择outputs及归档的notes/plans/writing文本，再交给04分析或构思。内部.deeptutor和.workbench不展示。

04新增接口：`GET /api/workbench/deeptutor/status`、`POST /api/workbench/deeptutor/topics/{topic}/handoffs`。03接口、读取和归档细节见[适配层](../adapters/deeptutor/README.md)。Python更新需重启03/04；workbench生产构建更新独立dist，03开发前端热更新、生产前端需重建，不重建04旧webui。

最小验收：选课题→少量勾选→去聊天→核对03参考清单→提问核对内容/引用→要求workspace_save保存文件→预览归档研究笔记→工作台刷新notes→本地修改归档.md→重新读取并选择04分析→切换课题核对隔离。真实模型由用户配置后主动发送；离线模拟不等同真实模型跑通。
