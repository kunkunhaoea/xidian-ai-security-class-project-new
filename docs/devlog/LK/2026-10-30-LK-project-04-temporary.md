## 1. 修复科研想法生成的文件名过长错误

### 本次目标

修复科研自动化页面点击“生成想法”后，因中文标题组成的文件名过长而返回 HTTP 500 的问题。

### 原因

`api/routers/scientist.py` 的 `_idea_file_label()` 将最多三个想法标题拼接为文件名，只限制字符数，没有限制 UTF-8 字节数。

本机文件系统单个文件名上限为255字节。此次报错对应的想法 JSON 文件名为251字节，可以保存；将后缀换成 `.meta.json` 后达到256字节，写入生成依据等元数据时触发 `OSError: [Errno 36] File name too long`。模型生成已完成，原想法 JSON 中已有5个想法，错误发生在后续保存阶段。

### 修改内容

- `projects/project-04-Intelligence Gathering/api/routers/scientist.py`
  - 保留时间戳和可读标题组成文件名的方式。
  - 将标题标签进一步限制在180个 UTF-8 字节内，为固定前缀、时间戳和较长的 `.meta.json` 后缀预留空间。
  - 截断时丢弃不完整的 UTF-8 字符，并清理末尾分隔符；JSON 内容及接口返回中的完整标题保持不变。
- `projects/project-04-Intelligence Gathering/tests/test_scientist_idea_filenames.py`
  - 新增离线回归测试，覆盖此次报错标题、超长中文、四字节 Unicode 字符、英文标题和空标题。
  - 模拟模型生成及知识库记录，调用生成接口处理函数，在临时目录实际写入 JSON 和元数据，并核验文件名长度、保存内容和返回标题。

本条修改不涉及公共共享目录约定、接口字段、模型配置或原有研究数据迁移。

## 2. 排查重复报错：运行中的后端未加载修复

### 现象与原因

用户再次生成想法时仍收到文件名过长的 HTTP 500。此次日志中的文件名为262字节，超过255字节限制；但磁盘上的 `_idea_file_label()` 已包含180字节限制。

核对发现：

- 8080端口对应的旧后端 PID 为63199，启动于2026-10-30 22:17:40，早于约22:46完成的上一条修复。
- `start.py` 使用普通 `uvicorn.run()`，没有启用自动重载。编辑源文件后，已有进程仍执行内存中的旧代码。
- 堆栈显示 `generate_ideas` 第1067行进入 `Path.write_text()`，但当前磁盘文件该行已是 `datetime.now().strftime(...)`。这是旧进程代码行号与修改后磁盘源码不一致的表现。

因此，本次重复报错的原因是后端未重新加载修复，并非180字节限制仍不足。无需再次缩短标题或修改命名规则。
