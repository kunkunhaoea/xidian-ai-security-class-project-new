# 共享知识库组织约定

本文约定四个项目共同使用的本地资料与成果如何组织。面向单人本地使用，以普通文件夹和原始文件为基础，研究记录采用 Markdown，支持通过 Obsidian、VS Code、PDF 阅读器等工具阅读，并由用户或经授权的 AI 编辑。

本文是组织约定，不代表四个项目已完成共享读写适配。

## 1. 基本原则

- 共享根目录固定为仓库根目录的 `shared/`，不同课题放在 `topics/<topic-id>/` 下，相互隔离。
- 普通文件是共享内容的依据，不以数据库作为共享资料的主存储；各项目可以保留自己的索引、缓存和运行状态。
- 论文、网页、README、代码、图片等保留适合阅读和编辑的原本格式，不强制转换成同一种格式。
- 每次任务由用户选择输入，默认不选择资料，不自动读取整个课题。
- 用户及各项目可以持续补充内容；重新采集、分析或导出不得直接覆盖已有人工修改。
- 研究方案可以持续编辑，每次执行单独归档，保留执行时的输入、方案和结果。
- `shared/` 中的个人资料与成果被 Git 忽略，不随仓库同步；本目录的 `README.md` 作为公共组织约定，可以随仓库提交。

## 2. 目录结构

每个课题使用以下五类目录：资料、笔记、方案、运行、写作。按需创建，不要求预先建立所有文件或空目录。

```text
shared/
├── README.md                          # 本约定
└── topics/
    └── agent-memory-security/         # 示例课题标识
        ├── README.md                  # 课题说明与导航
        ├── materials/                 # 外部参考资料
        │   ├── m001-memory-poisoning/
        │   │   ├── 来源.md
        │   │   ├── paper.pdf
        │   │   └── supplementary.pdf
        │   ├── m002-agent-framework/
        │   │   ├── 来源.md
        │   │   ├── README.md           # 原仓库 README
        │   │   └── repository/         # 按需保存的参考代码
        │   └── m003-security-discussion/
        │       ├── 来源.md
        │       └── content.md         # 网页或社交正文
        ├── notes/                     # 阅读、问答、讨论、分析与创新点
        │   ├── 文献阅读.md
        │   ├── 研究问题.md
        │   └── 创新点讨论.md
        ├── plans/                     # 可持续编辑的实验方案
        │   └── 记忆投毒实验.md
        ├── runs/                      # 每次实际执行的独立记录
        │   └── 2026-10-30-001/
        │       ├── README.md          # 执行说明、输入、状态及结果入口
        │       ├── inputs/            # 执行时的输入快照
        │       ├── code/
        │       ├── config/
        │       ├── logs/
        │       └── results/
        └── writing/                   # 论文与汇报草稿
            ├── 大纲.md
            ├── 论文草稿.md
            └── figures/
```

课题的 `README.md` 简要记录研究方向、当前进展及重要文件入口，不要求维护一份列出全部文件的清单。课题标识尽量保持稳定，显示名称可以在文档中修改。

## 3. 外部资料：一份资料一个文件夹

`materials/` 收纳论文、网页、GitHub 项目、社交内容和人工导入资料。不按采集平台划分第一层，也不强制拆成独立的学术库和社交库。

每份资料使用“课题内编号 + 简短名称”的目录，例如 `m001-memory-poisoning/`。编号在课题内唯一，标题修正时保留编号，目录路径尽量不变。

- PDF、README、图片及代码保留原文件。相关附件放在同一资料目录中。
- 网页或社交正文可以保存为 `content.md`，方便本地离线阅读。
- `来源.md` 记录资料身份、原始链接、获取情况及附件入口，不要求重复整篇正文。
- 相同资料再次采集时优先补充已有目录；可根据 DOI、arXiv ID、仓库地址或原始链接识别重复。
- 只有摘要或链接时，明确标注全文尚未下载。链接记录不等于已拥有全文。

`来源.md` 示例：

```markdown
# Memory Poisoning ...

- 资料编号：m001
- 类型：论文
- 原始链接：https://...
- 获取时间：2026-10-30
- 获取方式：项目04 / arXiv
- 附件状态：全文已下载
- 人工筛选：待阅读

## 简介

……

## 附件

- [论文全文](paper.pdf)
- [补充材料](supplementary.pdf)
```

以上是便于人工阅读的示例，不要求额外维护数据库、统一 JSON 清单或为每份资料填写大量字段。

## 4. 研究笔记：Markdown 与相对链接

`notes/` 保存阅读理解、选定问答、讨论、分析和创新点。按内容命名，一篇笔记可以引用多份资料，一份资料也可以被多篇笔记引用，不要求每篇论文生成固定数量的笔记。

引用使用普通 Markdown 相对链接。需要核验的论文证据注明页码或章节，并区分来源证据、AI 建议和人工判断。

```markdown
# 关于记忆投毒的研究问题

## 参考资料

- [论文 m001](../materials/m001-memory-poisoning/来源.md)
- [框架 m002](../materials/m002-agent-framework/来源.md)

## 论文证据

……（注明页码或章节）

## AI 建议

……

## 人工判断

……
```

对话由用户主动选择保存，不自动归档全部聊天记录。保存的研究笔记附上生成时间、参考资料和相关对话片段，正文可以继续编辑。

## 5. 方案与执行记录

`plans/` 保存用户和 AI 可以反复修改的实验方案。用户确认执行时，在 `runs/` 下创建独立目录，例如 `2026-10-30-001/`；同一天有多次执行时递增编号，不覆盖历史运行。

执行时将实际使用的方案、可编辑输入文档及配置保存为快照。例如：

```text
plans/记忆投毒实验.md
    → runs/2026-10-30-001/inputs/记忆投毒实验.md
```

后续编辑工作方案，不改变历史运行中的快照。PDF 等体积较大且内容固定的资料可以引用原文件，并记录可识别的版本信息；无法保证原文件保持不变时保存副本。不要求复制整个课题或完整参考代码仓库。

每次运行的 `README.md` 记录：

- 使用的项目或引擎，以及本次执行任务。
- 实际选用的资料与文档，及其快照或原文件位置。
- 使用的方案、代码和配置入口。
- 执行时间、当前状态、结果入口及实际失败原因。

运行目录按需保存 `inputs/`、`code/`、`config/`、`logs/` 和 `results/`。原项目必须在自己的工作区执行时，由适配层将需要交接和追溯的成果归档到对应运行目录。

任务输入选择需要被记录，但不强制在第一版额外建立 `inputs.yaml`。若后续适配层采用该文件，其作用是记录和转换输入；仅记录路径不能证明模型已实际使用资料。

## 6. 写作内容

`writing/` 保存论文大纲、正文草稿、引用资料及写作用图片等内容。草稿可以继续修改；实验原始结果保留在对应的 `runs/` 中，写作内容通过链接引用，必要时复制用于排版的图片。

## 7. 四个项目的默认读写位置

| 项目 | 主要读取 | 主要写入 |
| --- | --- | --- |
| 04 Intelligence Gathering | 检索要求、已有资料来源 | `materials/`；采集分析可写入 `notes/` |
| 03 DeepTutor | 用户选定的资料和研究文档 | `notes/`，以及经授权编辑的方案等 |
| 01 AI-Researcher | 用户选定的资料、笔记和方案 | `runs/`、`writing/`，必要时补充笔记 |
| 02 AI-Scientist-v2 | 用户选定的资料、想法和方案 | `runs/`、`writing/`，必要时补充笔记 |

这些是默认保存位置，不是严格权限划分；用户授权后，AI 可以修改指定文件。

各项目通过适配读取选定资料，并将成果保存到相应位置。03 的检索索引需要随选定资料的导入和修改建立或更新，不能将“文件已在 shared 中”等同于“已经可检索或已被模型使用”。

04 的内部采集数据、03 的检索索引及其他项目的临时缓存可以保留在各自目录。需要共同阅读和编辑的资料进入 `shared/`，内部索引可以根据文件重新建立。

## 8. 更新与保留规则

第一版不建设并发控制系统，统一遵守以下简单规则：

1. **按课题隔离**：每次操作明确当前课题，不串用其他课题的资料。
2. **按任务选择输入**：默认不读取整个课题，记录本次实际使用的资料。
3. **保留人工编辑**：再次采集、分析或导出时，不使用旧数据直接覆盖已编辑的来源说明、笔记和方案。有变化时补充附件或保存新版本，明确来源与时间。
4. **每次执行独立归档**：工作方案可以持续修改，历史运行保留执行时的输入和结果；失败运行也记录实际状态。

项目04现有导出目录向本结构的迁移、各项目输入转换和成果归档均属于后续适配工作，本文不自动迁移或改写已有资料。
